# Process — задачи, план, итерации, доклад

Как ведётся работа над задачами в glab-ios. Адаптировано из практики
platform (координатор/воркер), упрощено под одиночную сессию: здесь нет
Linear и оркестрации, но дисциплина «минимум церомонии» и «обсуждение ≠
старт» переносится целиком.

## Минимум церомонии

- Сложная задача — сначала план (AGENTS.md «Always plan first before
  coding»); план согласуется с пользователем, старт — по явному
  одобрению. Пока план обсуждается — **не работать** (файлы, коммиты,
  анализ): только отвечать и уточнять. Обсуждение ≠ старт:
  преждевременные действия — потерянная работа.
- Исследования — in-session Agent-вызовы (Explore/Plan) без правок
  файлов; не устраивать «карнавал» из агентов на каждый запрос.
- Тривиальные правки — сразу, без плана (AGENTS.md «Tradeoff»).

## Задачи и план

- Трекер — локальный: `.claude/tasks/` (одна задача = один файл,
  статусы open → in-progress → in-review → done в шапке; индекс —
  `.claude/tasks/README.md`). Планы — `.claude/plans/`
  (`YYYY-MM-DD-<slug>.md`). Linear пока нет; когда появится — мигрировать
  по правилам platform (постановка в тикет, отчёт — комментарий).
- Большой план разбивается на фазы-задачи; каждая фаза самостоятельна
  и проверяема в симуляторе (текущий: `plans/2026-11-07-glab-clone.md`,
  фазы 1–6, задачи — `tasks/2026-11-07-glab-clone-phase-{1..6}.md`).
- Одна фаза = один сеанс работы; следующая фаза не стартует, пока
  текущая не проверена (скриншоты в симуляторе) и не одобрена
  пользователем. Статус задачи меняется на in-review после доклада, в
  done — после одобрения пользователем.
- План живёт в файле плана, а не в памяти сессии; по завершении
  компакции контекста — сверяться с файлом плана и задачей.

## Итерации и проверки (из verification-практики platform)

Проверки масштабируются по blast radius, а не «на всякий случай».
Ярусы:

| Ярус | Что | Когда | Цена |
|---|---|---|---|
| 0 | сборка `xcodebuild … build` с переиспользованием derivedData | в процессе, после правок | ~минута |
| 1 | точечные тесты затронутого модуля (`xcodebuild test -only-testing:<Suite>`) | после содержательной итерации | секунды–минуты |
| 2 | полный тест-сьют | **один раз**, перед завершением задачи (AGENTS.md) | минуты |

- Упавший тест чинится на месте — перезапускать только его, не весь
  скоуп. Полный прогон — один раз, на финальном состоянии; в процессе
  правок полный гейт не гонять (состояние ещё меняется).
- UI-проверка обязательна: сборка и скриншоты в симуляторе (AGENTS.md
  «Use the ios simulator to test your changes»); интерактивная проверка
  — превью-страница эмулятора или `orca emulator tap/ax`.
- Прогон в лог с уникальным именем: `… > /tmp/xcodebuild-<suffix>.log
  2>&1; tail -n 20` — читать только итог; при успехе лог удалить.

## Коммиты

- Не коммитить без явного запроса пользователя (AGENTS.md-правило
  Claude Code + практика platform «агенты не коммитят без явного
  запроса владельца»).
- Формат — по конвенции репо: `feat: …` / `bug: …` / `docs: …`,
  английский, тема ≤ 100 символов + тело с деталями.
- Пуш и создание PR — только по явному слову пользователя.

## Доклад по завершении фазы

Короткий итог: что сделано, что проверено (скриншоты/тапы в
симуляторе), какие отклонения от плана возникли и почему, что
предлагаю дальше (следующая фаза). Отклонение от плана не молча —
с пометкой в докладе.
